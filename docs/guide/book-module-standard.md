# Book Module 专栏规范

Book Module 用于承载一个主题下具有明确学习顺序的完整课程。Git 是知识库的第一个 Book Module，后续 Docker、Cloudflare、MCP、Agent 专栏沿用本规范。

## 一、适用范围

当一个主题同时满足以下条件时，适合使用 Book Module：

- 内容由多个互相衔接的章节组成。
- 读者需要按照推荐顺序学习。
- 每章都具备完整内容，而不是只有标题的占位页。
- 整个专栏具有统一的目标、受众和完成标准。

彼此独立、没有阅读顺序的文章继续使用普通分类，不需要做成专栏。

## 二、目录结构

每个专栏使用独立目录：

```text
docs/
└── <book-slug>/
    ├── index.md
    ├── chapters/
    │   ├── 01-first-topic.md
    │   ├── 02-second-topic.md
    │   └── ...
    └── <appendix>.md
```

- `index.md` 是专栏首页，包含定位、受众、学习成果和课程目录。
- `chapters/` 保存按顺序编号的正文。
- 附录放在专栏根目录，不占用主课程章节编号。
- 文件名使用两位数字前缀和英文短横线命名。

## 三、专栏配置

专栏元数据统一维护在 `docs/.vitepress/book-modules.ts`。

每个专栏需要声明：

- `title`：专栏名称。
- `icon`：导航图标。
- `base`：专栏根路径。
- `sections`：课程阶段及章节列表。
- `appendices`：可选附录。

章节条目统一包含：

- `text`：侧边栏显示名称。
- `link`：章节链接。
- `description`：专栏首页的章节摘要。

`createBookSidebar()` 会根据相同数据生成专栏侧边栏。新增专栏时不应复制一套手写导航逻辑。

## 四、专栏首页

专栏首页应包含：

1. 专栏名称和一句话定位。
2. 适合人群与前置知识。
3. 章节数、学习阶段和内容定位。
4. “开始阅读”入口。
5. 按学习阶段排列的完整课程目录。
6. 学完后能够获得的具体能力。

首页使用通用组件：

```md
<BookLanding book-id="<book-id>" />
```

组件会读取 `book-modules.ts` 中的专栏数据，生成封面、统计信息、受众说明和章节卡片。新增主题时不应复制 Git 专栏首页的 HTML。

## 五、章节结构

每章只保留一个一级标题，推荐结构如下：

```markdown
---
outline: deep
---

# 第 N 章：章节标题

> 本章核心结论或定位。

## 本章目标

## 核心知识

## 实际案例

## 实验室

## 常见误区

## 本章总结
```

章节可以根据内容增减小节，但应尽量包含目标、原理、实践、风险和总结。

## 六、阅读导航

- 专栏页面使用独立侧边栏，不与普通知识库目录混排。
- 侧边栏按学习阶段分组，并保持章节编号连续。
- VitePress 根据侧边栏顺序生成上一篇和下一篇入口。
- 专栏首页必须能够直接进入第一章。
- 旧版单篇指南可以保留为附录，但不能打断主课程顺序。

## 七、发布检查

发布前至少完成：

- 所有章节只有一个一级标题。
- 章节文件名、目录顺序和侧边栏配置一致。
- 内部链接可以通过知识库构建检查。
- 高风险命令包含明确的使用场景和警告。
- 首页在桌面端和移动端都能正常阅读。
- 专栏首页、第一章、最后一章和附录都能在线访问。

## 八、新专栏接入流程

1. 创建专栏目录和章节文件。
2. 在 `book-modules.ts` 中声明专栏及章节。
3. 使用 `createBookSidebar()` 接入独立侧边栏。
4. 使用通用 Book Module 样式制作专栏首页。
5. 将专栏入口加入顶部导航和知识库首页。
6. 完成构建、链接检查和线上验证。

专栏升级时保留原有目录、链接和导航入口，直接更新现有内容。专栏首页、标题、导航和卡片不展示发布版本号。
