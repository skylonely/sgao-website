# 2. 软件架构设计类案例

高频考点：

-   架构风格；
-   分层架构；
-   C/S与B/S；
-   架构模式。

常见回答：

> 采用分层架构降低模块耦合，提高系统可维护性和扩展能力。

# 3. 软件质量属性类案例

重点：

  属性       策略
  ---------- ----------------------
  性能       缓存、集群、负载均衡
  可用性     冗余、故障转移
  安全性     认证、授权、加密
  可修改性   分层、模块化
  可靠性     容错、备份

------------------------------------------------------------------------

# 4. MVC / SOA / ESB类案例

## MVC

重点：

-   Model；
-   View；
-   Controller。

作用：

> 分离表现层和业务逻辑，提高可维护性。

------------------------------------------------------------------------

## SOA

重点：

-   服务提供者；
-   服务消费者；
-   服务注册中心。

作用：

> 实现服务复用和系统松耦合。

------------------------------------------------------------------------

## ESB

重点：

-   消息转换；
-   协议转换；
-   服务路由。

作用：

> 解决异构系统集成问题。

------------------------------------------------------------------------

# 5. 数据库系统类案例

重点：

-   主从复制；
-   读写分离；
-   分库分表；
-   数据库优化。

常见回答：

> 通过读写分离降低数据库压力，通过分库分表提高数据扩展能力。

------------------------------------------------------------------------

# 11. 案例答题流程

## 第一步：识别关键词

例如：

高并发：

→ 缓存、负载均衡、集群。

高可靠：

→ 冗余、容错、备份。

高安全：

→ 认证、授权、加密。

------------------------------------------------------------------------

## 第二步：选择架构策略

根据需求选择：

-   架构模式；
-   技术方案；
-   管理措施。

------------------------------------------------------------------------

## 第三步：使用专业术语

避免：

-   口语描述；
-   模糊表达。

# 13. 易错点总结

  错误理解               正确理解
  ---------------------- ----------------------
  缓存解决所有性能问题   缓存主要降低访问压力
  MVC是数据库结构        MVC是应用架构模式
  SOA等于Web Service     SOA是一种架构思想
  关键路径最短           关键路径是最长路径
  IDS可以阻止攻击        IDS主要检测报警
