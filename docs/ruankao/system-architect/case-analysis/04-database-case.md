# 2. 数据库架构设计案例

常见架构：

## 单数据库架构

特点：

-   结构简单；
-   易维护。

问题：

-   扩展能力有限；
-   容易出现性能瓶颈。

------------------------------------------------------------------------

## 主从数据库架构

``` text
应用

↓

主数据库

↓

从数据库
```

特点：

-   主库负责写；
-   从库负责读。

------------------------------------------------------------------------

## 分布式数据库架构

特点：

-   数据分布存储；
-   支持水平扩展；
-   提升处理能力。

------------------------------------------------------------------------

# 3. 数据库性能优化案例

常见问题：

-   查询慢；
-   并发高；
-   数据量增长快。

优化措施：

## 索引优化

提高查询效率。

注意：

索引过多会增加写入成本。

------------------------------------------------------------------------

## SQL优化

包括：

-   减少无效查询；
-   优化复杂SQL；
-   合理使用查询条件。

------------------------------------------------------------------------

## 缓存优化

例如：

-   Redis；
-   本地缓存。

作用：

减少数据库压力，提高响应速度。

------------------------------------------------------------------------

# 4. 数据库分库分表案例

适用：

-   单表数据量过大；
-   数据库压力过高。

## 垂直拆分

按照业务拆分：

``` text
用户库

订单库

商品库
```

------------------------------------------------------------------------

## 水平拆分

按照数据规则拆分：

``` text
用户表1

用户表2

用户表3
```

# 5. 主从复制与读写分离案例

结构：

``` text
写请求

↓

主数据库

↓

数据同步

↓

从数据库

↓

读请求
```

优势：

-   提升读取性能；
-   降低主库压力。

需要关注：

-   数据同步延迟；
-   数据一致性。

# 10. 案例分析答题模板

## 数据库压力大

答案：

> 采用读写分离架构，将写操作集中到主数据库，将读操作分散到多个从数据库，提高系统并发处理能力。

------------------------------------------------------------------------

## 数据快速增长

答案：

> 采用分库分表策略，根据业务特点进行垂直拆分或水平拆分，提高数据库扩展能力。

------------------------------------------------------------------------

## 查询速度慢

答案：

> 通过索引优化、SQL优化以及缓存机制降低数据库访问压力，提高查询效率。
