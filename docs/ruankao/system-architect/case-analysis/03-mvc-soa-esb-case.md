# 2. MVC架构案例（★★★★★）

MVC是一种经典的软件架构模式。

核心思想：

> 将用户界面、业务逻辑和数据处理进行分离。

MVC包括：

``` text
MVC

├── Model
├── View
└── Controller
```

------------------------------------------------------------------------

# 3. MVC三个组成部分

## 3.1 Model（模型）

职责：

-   管理数据；
-   实现业务逻辑；
-   处理业务规则。

特点：

与用户界面无关。

------------------------------------------------------------------------

## 3.2 View（视图）

职责：

-   展示用户界面；
-   显示处理结果。

特点：

负责表现，不负责业务处理。

------------------------------------------------------------------------

## 3.3 Controller（控制器）

职责：

-   接收用户请求；
-   调用模型处理业务；
-   选择返回视图。

------------------------------------------------------------------------

# 5. MVC案例答题模板

## 场景

系统页面变化频繁，需要提高可维护性。

答案：

> 采用MVC架构，将表示层、业务逻辑和数据处理分离，降低模块之间耦合，提高系统可维护性和可扩展性。

------------------------------------------------------------------------

# 6. SOA架构案例（★★★★★）

SOA：

Service-Oriented Architecture。

即：

> 面向服务架构。

核心思想：

将业务功能封装为可复用服务，通过服务接口实现系统之间的松耦合集成。

------------------------------------------------------------------------

# 7. SOA核心组成

## 服务提供者

负责：

-   发布服务；
-   提供服务能力。

------------------------------------------------------------------------

## 服务消费者

负责：

-   查找服务；
-   调用服务。

------------------------------------------------------------------------

## 服务注册中心

负责：

-   服务登记；
-   服务发现。

------------------------------------------------------------------------

结构：

``` text
服务提供者

↓

服务注册中心

↓

服务消费者
```

------------------------------------------------------------------------

# 8. SOA主要特点

## 服务复用

已有业务能力可以被多个系统使用。

------------------------------------------------------------------------

## 松耦合

系统之间通过服务接口通信。

------------------------------------------------------------------------

## 服务自治

服务具有相对独立性。

------------------------------------------------------------------------

## 服务组合

多个服务可以组合完成复杂业务。

------------------------------------------------------------------------

# 9. SOA案例答题模板

## 场景

企业多个系统需要共享业务能力。

答案：

> 采用SOA架构，将业务功能封装为服务，通过标准服务接口实现系统集成，提高服务复用能力，降低系统之间耦合。

------------------------------------------------------------------------

# 10. ESB企业服务总线案例（★★★★★）

ESB：

Enterprise Service Bus。

作用：

> 在SOA架构中提供服务通信和集成能力。

------------------------------------------------------------------------

# 11. ESB核心功能

## 11.1 消息转换

解决：

不同系统消息格式不一致。

------------------------------------------------------------------------

## 11.2 协议转换

解决：

不同通信协议之间转换。

例如：

-   HTTP；
-   SOAP；
-   JMS。

------------------------------------------------------------------------

## 11.3 服务路由

根据规则：

将请求发送到对应服务。

------------------------------------------------------------------------

## 11.4 服务监控

提供：

-   服务状态监控；
-   日志管理。

------------------------------------------------------------------------

# 12. ESB案例答题模板

## 场景

多个异构系统需要通信。

答案：

> 引入ESB作为企业服务总线，实现消息转换、协议适配和服务路由，屏蔽不同系统之间的差异，提高系统集成能力。

------------------------------------------------------------------------

# 13. MVC、SOA、ESB关系分析

三者解决的问题不同：

  技术   主要解决问题
  ------ --------------------
  MVC    应用内部职责分离
  SOA    企业系统服务化集成
  ESB    服务之间通信和转换

关系：

``` text
MVC

↓

应用内部设计

SOA

↓

系统服务化

ESB

↓

服务集成通信
```

------------------------------------------------------------------------

# 14. SOA与微服务区别

  对比       SOA          微服务
  ---------- ------------ ----------
  服务粒度   较大         较小
  通信方式   常依赖ESB    轻量通信
  部署方式   集中式较多   独立部署
  目标       企业集成     快速演进

# 19. 本节小结

MVC、SOA、ESB是系统架构设计师案例分析的重要考点。

核心理解：

-   MVC解决应用内部职责划分；
-   SOA解决企业系统服务化；
-   ESB解决服务之间通信和集成。

案例回答核心：

> 先识别系统问题，再选择合适架构模式，并说明其带来的质量属性提升。
