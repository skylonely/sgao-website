# 1. 软件架构案例概述

软件架构设计案例主要考查：

-   根据系统需求选择合适架构；
-   分析架构优缺点；
-   根据质量属性进行架构优化；
-   使用架构模式解决实际问题。

案例题通常给出：

-   系统背景；
-   业务需求；
-   性能、安全、扩展等要求；

要求分析：

-   架构方案；
-   设计理由；
-   技术措施。

------------------------------------------------------------------------

# 2. 软件架构基本概念

软件架构是：

> 软件系统的结构以及结构之间关系的抽象描述。

主要包括：

-   构件；
-   连接件；
-   配置。

------------------------------------------------------------------------

# 3. 常见软件架构风格（★★★★★）

## 3.1 数据流风格

特点：

数据按照一定流程经过多个处理阶段。

典型：

-   编译器；
-   ETL处理。

优点：

-   易于扩展；
-   处理流程清晰。

缺点：

-   数据格式变化影响较大。

------------------------------------------------------------------------

## 3.2 调用返回风格

特点：

通过调用关系组织系统。

包括：

-   主程序/子程序；
-   面向对象调用。

优点：

-   结构清晰；
-   易理解。

------------------------------------------------------------------------

## 3.3 分层架构

典型：

``` text
表示层

↓

业务层

↓

数据访问层

↓

数据库层
```

优点：

-   职责分离；
-   易维护；
-   易扩展。

------------------------------------------------------------------------

## 3.4 仓库风格

特点：

多个构件共享中心数据。

例如：

-   数据库系统；
-   信息管理系统。

------------------------------------------------------------------------

## 3.5 客户端/服务器架构

特点：

客户端负责交互，服务器提供服务。

------------------------------------------------------------------------

# 4. C/S与B/S架构案例

## C/S架构

结构：

``` text
客户端

↓

服务器
```

优点：

-   响应速度快；
-   客户端功能强。

缺点：

-   部署维护困难；
-   升级成本高。

------------------------------------------------------------------------

## B/S架构

结构：

``` text
浏览器

↓

Web服务器

↓

数据库
```

优点：

-   易部署；
-   易维护；
-   跨平台。

缺点：

-   对服务器压力较大。

------------------------------------------------------------------------

# 5. 分层架构案例

分层架构设计重点：

## 表示层

负责：

-   用户交互；
-   页面展示。

------------------------------------------------------------------------

## 业务层

负责：

-   业务规则；
-   业务流程。

------------------------------------------------------------------------

## 数据层

负责：

-   数据访问；
-   数据存储。

------------------------------------------------------------------------

案例答题：

当题目要求：

"提高系统可维护性"

可回答：

-   采用分层架构；
-   降低模块耦合；
-   提高系统可扩展性。

------------------------------------------------------------------------

# 6. MVC架构案例（★★★★★）

MVC：

``` text
Model

View

Controller
```

## Model

负责：

-   数据；
-   业务逻辑。

------------------------------------------------------------------------

## View

负责：

-   用户界面展示。

------------------------------------------------------------------------

## Controller

负责：

-   接收请求；
-   调用业务；
-   返回结果。

------------------------------------------------------------------------

优势：

-   分离表现和业务；
-   提高可维护性。

------------------------------------------------------------------------

# 7. SOA架构案例（★★★★★）

SOA：

面向服务架构。

核心思想：

> 将系统功能封装为可复用服务。

主要特点：

-   服务自治；
-   服务复用；
-   松耦合。

------------------------------------------------------------------------

典型组件：

-   服务提供者；
-   服务消费者；
-   服务注册中心。

------------------------------------------------------------------------

# 8. DSSA与ABSD案例

## DSSA

领域特定软件架构。

重点：

针对特定领域建立：

-   领域模型；
-   可复用架构。

------------------------------------------------------------------------

## ABSD

基于架构的软件设计。

核心过程：

``` text
需求分析

↓

架构设计

↓

架构实现

↓

架构评估
```

------------------------------------------------------------------------

# 9. 软件架构设计原则

## 高内聚低耦合

目标：

-   降低模块依赖；
-   提高可维护性。

------------------------------------------------------------------------

## 面向变化设计

考虑：

-   扩展需求；
-   技术变化。

------------------------------------------------------------------------

## 关注质量属性

例如：

性能：

-   缓存；
-   负载均衡。

可用性：

-   冗余；
-   故障转移。

安全性：

-   身份认证；
-   权限控制。

------------------------------------------------------------------------
