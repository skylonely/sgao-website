# 1. NoSQL数据库案例概述

NoSQL案例主要考查：

-   海量数据存储；
-   高并发访问；
-   分布式扩展；
-   灵活数据结构；
-   非关系型数据管理。

案例通常给出：

-   用户数量快速增长；
-   数据规模巨大；
-   查询压力增加；
-   数据结构变化频繁。

要求分析：

-   是否采用NoSQL；
-   选择何种NoSQL类型；
-   说明技术优势。

------------------------------------------------------------------------

# 2. NoSQL产生背景（★★★★★）

传统关系数据库面临：

-   数据规模快速增长；
-   高并发访问压力；
-   水平扩展困难；
-   数据结构变化频繁。

发展过程：

``` text
数据规模增长

↓

关系数据库扩展压力

↓

分布式存储需求

↓

NoSQL出现
```

------------------------------------------------------------------------

# 3. NoSQL基本概念

NoSQL：

> Not Only SQL。

并不是"不使用SQL"，而是表示：

> 除关系数据库之外的其他数据存储方式。

特点：

-   非关系模型；
-   支持水平扩展；
-   高并发处理能力；
-   数据结构灵活。

------------------------------------------------------------------------

# 4. NoSQL数据库分类

## 4.1 Key-Value数据库

特点：

-   键值存储；
-   查询速度快；
-   结构简单。

代表：

-   Redis；
-   MemCache。

适合：

-   缓存；
-   会话管理；
-   计数统计。

------------------------------------------------------------------------

## 4.2 文档数据库

特点：

-   存储文档数据；
-   支持JSON/BSON结构；
-   数据模型灵活。

适合：

-   内容管理；
-   半结构化数据。

------------------------------------------------------------------------

## 4.3 列族数据库

特点：

-   面向大规模分布式数据；
-   支持海量数据存储。

------------------------------------------------------------------------

## 4.4 图数据库

特点：

-   描述实体之间关系；
-   适合关系网络分析。

------------------------------------------------------------------------

# 5. CAP理论案例（★★★★★）

CAP包括：

  属性                       含义
  -------------------------- ------------
  C（Consistency）           一致性
  A（Availability）          可用性
  P（Partition Tolerance）   分区容错性

核心：

> 分布式系统无法同时完全满足CAP三个要求。

------------------------------------------------------------------------

## 案例分析

如果系统要求：

-   高可用；
-   分布式部署；

通常需要在一致性和可用性之间进行权衡。

------------------------------------------------------------------------

# 6. BASE模型案例（★★★★★）

BASE：

## Basically Available

基本可用。

------------------------------------------------------------------------

## Soft State

软状态。

------------------------------------------------------------------------

## Eventually Consistent

最终一致。

------------------------------------------------------------------------

与ACID区别：

  ACID             BASE
  ---------------- ----------------
  强一致           最终一致
  事务优先         可用性优先
  关系数据库常见   分布式系统常见

------------------------------------------------------------------------

# 7. Redis案例分析（★★★★★）

Redis属于：

Key-Value数据库。

常见应用：

## 缓存

减少数据库访问。

------------------------------------------------------------------------

## Session存储

保存用户会话信息。

------------------------------------------------------------------------

## 计数器

例如：

-   浏览次数；
-   点赞数量。

------------------------------------------------------------------------

## 排行榜

利用有序集合实现。

------------------------------------------------------------------------

优势：

-   内存访问速度快；
-   支持高并发。

注意：

需要考虑：

-   数据持久化；
-   缓存一致性。

------------------------------------------------------------------------

# 8. MemCache案例分析

MemCache：

基于内存的Key-Value缓存系统。

特点：

-   结构简单；
-   访问速度快；
-   适合作为缓存。

适用：

-   临时数据；
-   热点数据。

------------------------------------------------------------------------

# 9. 文档数据库案例

文档数据库特点：

-   数据结构灵活；
-   不需要固定表结构；
-   适合半结构化数据。

应用：

-   内容管理系统；
-   用户配置数据；
-   日志数据。

------------------------------------------------------------------------

# 10. NoSQL与关系数据库对比

  对比       关系数据库     NoSQL
  ---------- -------------- --------------
  数据结构   表结构         灵活结构
  扩展方式   垂直扩展较多   水平扩展
  一致性     强一致         最终一致较多
  事务       支持强事务     根据模型不同
  场景       事务业务       海量、高并发

# 11. NoSQL应用场景案例

## 场景一：热点数据访问频繁

问题：

数据库压力大。

方案：

> 使用Redis缓存热点数据，减少数据库访问。

------------------------------------------------------------------------

## 场景二：海量非结构化数据

问题：

传统数据库扩展困难。

方案：

> 使用NoSQL分布式存储，提高数据扩展能力。

------------------------------------------------------------------------

## 场景三：数据结构变化频繁

问题：

表结构修改成本高。

方案：

> 使用文档数据库，提高数据模型灵活性。

------------------------------------------------------------------------

# 12. 案例分析答题模板

## 高并发缓存场景

答案：

> 使用Redis等Key-Value数据库作为缓存层，将热点数据存储在内存中，减少关系数据库访问压力，提高系统响应速度。

------------------------------------------------------------------------

## 海量数据场景

答案：

> 采用NoSQL数据库，通过分布式存储和水平扩展能力满足大规模数据存储需求。

------------------------------------------------------------------------

## 灵活数据结构场景

答案：

> 采用文档数据库，支持非固定结构数据存储，提高系统扩展能力。

------------------------------------------------------------------------
