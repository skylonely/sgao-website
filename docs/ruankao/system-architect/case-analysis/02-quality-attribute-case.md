# 1. 软件质量属性案例概述

软件质量属性是评价软件系统的重要指标。

案例分析中通常不会直接询问：

"什么是性能？"

而是通过场景描述考查：

-   如何识别质量属性；
-   如何选择架构策略；
-   如何说明技术措施。

基本分析过程：

``` text
需求场景

↓

识别质量属性

↓

选择架构策略

↓

提出技术措施
```

------------------------------------------------------------------------

# 2. 质量属性场景分析方法

案例题中的关键词通常对应质量属性。

  需求关键词               质量属性
  ------------------------ ----------
  快速响应、大量用户访问   性能
  不能停止服务             可用性
  防止非法访问             安全性
  方便修改扩展             可修改性
  方便测试                 可测试性
  长时间稳定运行           可靠性

# 3. 性能案例（★★★★★）

## 3.1 性能概念

性能关注：

-   响应时间；
-   吞吐量；
-   并发处理能力。

------------------------------------------------------------------------

## 3.2 常见架构策略

### 缓存

作用：

-   减少数据库访问；
-   提高响应速度。

例如：

-   Redis缓存；
-   本地缓存。

------------------------------------------------------------------------

### 负载均衡

作用：

-   分散请求压力；
-   提高系统处理能力。

------------------------------------------------------------------------

### 集群

作用：

-   增加服务处理能力；
-   支持高并发。

------------------------------------------------------------------------

### 异步处理

作用：

-   降低请求等待时间；
-   提高系统吞吐量。

------------------------------------------------------------------------

## 性能案例答题模板

场景：

> 系统访问量大，需要快速响应。

答案：

-   使用缓存减少重复计算；
-   使用负载均衡分发请求；
-   采用服务器集群提高处理能力；
-   使用异步处理提高吞吐量。

------------------------------------------------------------------------

# 4. 可用性案例（★★★★★）

## 4.1 可用性概念

可用性关注：

> 系统持续提供服务的能力。

------------------------------------------------------------------------

## 4.2 常见架构策略

### 冗余设计

例如：

-   双机部署；
-   多节点部署。

------------------------------------------------------------------------

### 故障转移

作用：

当一个节点故障时：

自动切换到备用节点。

------------------------------------------------------------------------

### 心跳检测

作用：

-   检测节点状态；
-   发现故障。

------------------------------------------------------------------------

## 可用性案例答题模板

场景：

> 系统要求全年稳定运行。

答案：

-   采用冗余部署；
-   使用故障转移机制；
-   增加健康检查和心跳检测。

------------------------------------------------------------------------

# 5. 安全性案例（★★★★★）

安全性关注：

-   保密性；
-   完整性；
-   可控性。

------------------------------------------------------------------------

## 常见架构策略

### 身份认证

确认：

用户身份是否合法。

------------------------------------------------------------------------

### 授权控制

限制：

用户访问权限。

------------------------------------------------------------------------

### 数据加密

保护：

-   传输数据；
-   存储数据。

------------------------------------------------------------------------

### 审计

记录：

-   用户操作；
-   安全事件。

------------------------------------------------------------------------

# 6. 可修改性案例（★★★★★）

可修改性关注：

系统面对变化时的调整能力。

------------------------------------------------------------------------

## 常见策略

### 模块化

降低模块之间影响。

------------------------------------------------------------------------

### 分层架构

例如：

``` text
表示层

业务层

数据层
```

提高维护能力。

------------------------------------------------------------------------

### 接口隔离

通过接口降低依赖。

------------------------------------------------------------------------

### 松耦合

减少模块之间关联。

------------------------------------------------------------------------

# 7. 可测试性案例

可测试性关注：

系统是否容易验证。

常用策略：

-   模块独立；
-   接口标准化；
-   自动化测试；
-   测试环境隔离。

------------------------------------------------------------------------

# 8. 可靠性案例（★★★★★）

可靠性关注：

系统长期稳定运行能力。

常见策略：

## 容错设计

例如：

-   异常处理；
-   错误恢复。

------------------------------------------------------------------------

## 备份恢复

保证：

数据不会因为故障丢失。

------------------------------------------------------------------------

## 冗余机制

减少单点故障。

------------------------------------------------------------------------

# 9. 易用性案例

易用性关注：

用户使用系统的方便程度。

常见策略：

-   简洁界面；
-   操作提示；
-   用户反馈；
-   帮助机制。

------------------------------------------------------------------------

# 10. 质量属性与架构策略对应表

  质量属性   常用策略
  ---------- ----------------------------
  性能       缓存、负载均衡、集群、异步
  可用性     冗余、故障转移、心跳检测
  安全性     认证、授权、加密、审计
  可修改性   分层、模块化、接口隔离
  可测试性   自动化测试、模块隔离
  可靠性     容错、备份、恢复

------------------------------------------------------------------------

# 11. 案例答题模板

## 模板一：性能优化

> 针对系统访问量大的问题，可以采用缓存机制减少数据库访问，通过负载均衡和集群提高系统处理能力，同时采用异步处理提升吞吐量。

------------------------------------------------------------------------

## 模板二：高可用设计

> 通过冗余部署避免单点故障，结合故障转移和健康检测机制，提高系统可用性。

------------------------------------------------------------------------

## 模板三：可维护设计

> 采用分层架构和模块化设计，通过接口隔离降低模块耦合，提高系统可修改性。

------------------------------------------------------------------------

# 12. 高频考点（★★★★★）

重点掌握：

2.  性能优化措施；
3.  高可用设计方法；
4.  安全架构策略；
5.  分层和模块化提升可维护性；
6.  质量属性与架构策略匹配。

------------------------------------------------------------------------

# 13. 易错点

  易错知识               正确理解
  ---------------------- --------------------
  缓存只能提高可靠性     缓存主要提升性能
  冗余主要解决性能       冗余主要提升可用性
  分层一定提升性能       分层主要提升维护性
  加密可以代替权限控制   加密和授权作用不同

# 15. 本节小结

软件质量属性案例是系统架构设计师案例分析中的核心考点。

1.  从需求描述识别质量属性；

3.  使用专业术语描述技术措施。

> 需求场景 → 质量属性 → 架构策略 → 技术措施。
