# 1. 容错设计概述

容错设计（Fault Tolerance Design）是提高软件可靠性的重要方法。

目标：

> 当系统出现错误或故障时，仍能够继续提供正确服务。

容错设计关注：

-   错误检测；
-   故障隔离；
-   错误恢复。

------------------------------------------------------------------------

# 2. 容错基本思想

基本流程：

``` text
错误发生

↓

错误检测

↓

错误处理

↓

系统恢复

↓

继续运行
```

------------------------------------------------------------------------

# 3. 容错技术分类

## 3.1 检错技术

用于发现运行中的错误：

-   数据检查
-   状态检查
-   边界检查

## 3.2 屏蔽技术

隐藏错误影响：

-   冗余设计
-   多版本执行

## 3.3 恢复技术

故障后恢复：

-   回滚恢复
-   备用模块切换

------------------------------------------------------------------------

# 4. 冗余技术

冗余通过增加额外资源提高可靠性。

## 4.1 结构冗余

增加备用硬件或软件模块。

## 4.2 信息冗余

增加校验信息：

-   校验码
-   校验位

## 4.3 时间冗余

重复执行：

-   重新计算
-   重复运行

------------------------------------------------------------------------

# 5. 表决技术

表决技术用于多个结果中选择正确结果。

流程：

``` text
多个程序执行

↓

结果比较

↓

表决器

↓

输出结果
```

------------------------------------------------------------------------

# 6. N版本程序设计

N版本程序设计是一种静态冗余容错技术。

思想：

多个独立团队开发多个不同版本程序。

结构：

``` text
版本1
版本2
版本N

↓

表决器

↓

正确结果
```

特点：

-   降低单一错误影响；
-   提高可靠性；
-   要求版本之间尽量独立。

------------------------------------------------------------------------

# 7. 恢复块设计

恢复块设计是一种动态冗余技术。

组成：

-   主模块
-   备用模块
-   验收测试

流程：

``` text
执行主模块

↓

验收测试

↓

成功输出

↓

失败切换备用模块
```

特点：

优点：

-   资源利用率较高；
-   支持错误恢复。

缺点：

-   需要可靠验收测试；
-   增加系统复杂度。

------------------------------------------------------------------------

# 8. N版本程序设计与恢复块设计对比

  对比项     N版本程序设计    恢复块设计
  ---------- ---------------- ------------
  类型       静态冗余         动态冗余
  执行方式   多版本同时执行   主模块优先
  判断方式   表决器           验收测试
  资源消耗   较高             相对较低

# 11. 易错点

  易错知识            正确理解
  ------------------- ------------------------
  容错是不产生错误    容错是在错误后继续运行
  N版本只有一个程序   N版本包含多个独立版本
  恢复块是静态冗余    恢复块属于动态冗余
  冗余主要提升性能    冗余主要提升可靠性
