# 1. 软件可靠性设计概述

软件可靠性设计是在软件设计阶段，通过采用合理的设计方法，提高软件运行可靠性的过程。

主要目标：

-   降低软件故障发生概率；
-   提高软件容错能力；
-   提高系统可用性；
-   增强软件运行稳定性。

软件可靠性设计通常包括：

-   容错设计；
-   检错设计；
-   冗余设计；
-   恢复设计。

------------------------------------------------------------------------

# 2. 软件可靠性设计原则

软件可靠性设计主要遵循以下原则：

## 2.1 简化设计

降低系统复杂度：

-   减少不必要功能；
-   降低模块耦合；
-   提高可维护性。

------------------------------------------------------------------------

## 2.2 模块化设计

通过模块划分：

-   降低错误影响范围；
-   便于测试和维护。

------------------------------------------------------------------------

## 2.3 容错设计

即使发生错误，也能够保持系统继续运行。

------------------------------------------------------------------------

## 2.4 可恢复设计

系统发生故障后，可以恢复到正常状态。

------------------------------------------------------------------------

# 3. 容错设计

容错设计（Fault Tolerance Design）是指：

> 软件系统出现错误或故障时，仍能够继续提供正确服务的设计方法。

核心思想：

``` text
发现错误

↓

处理错误

↓

继续运行
```

容错技术主要包括：

-   错误检测；
-   故障隔离；
-   错误恢复。

------------------------------------------------------------------------

# 4. 检错设计

检错设计（Error Detection Design）主要用于发现软件运行中的错误。

常见方法：

-   输入数据检查；
-   输出结果检查；
-   状态检查；
-   边界检查。

特点：

-   可以发现错误；
-   不能保证系统自动恢复。

------------------------------------------------------------------------

# 5. 冗余设计

冗余设计通过增加额外资源，提高系统可靠性。

主要类型：

## 5.1 结构冗余

增加硬件或软件模块。

例如：

-   备用模块；
-   多个执行单元。

------------------------------------------------------------------------

## 5.2 信息冗余

增加额外校验信息。

例如：

-   校验码；
-   校验位。

------------------------------------------------------------------------

## 5.3 时间冗余

通过重复执行提高可靠性。

例如：

-   重新计算；
-   重复执行。

------------------------------------------------------------------------

# 6. N版本程序设计

N版本程序设计是一种典型的软件容错技术。

基本思想：

由多个独立开发团队开发多个不同版本的软件。

结构：

``` text
版本1

版本2

版本N

   ↓

表决器

   ↓

输出正确结果
```

------------------------------------------------------------------------

## N版本程序设计特点

优点：

-   降低单一程序错误影响；
-   提高系统可靠性。

要求：

-   各版本相互独立；
-   尽量避免相同错误。

------------------------------------------------------------------------

# 7. 恢复块设计

恢复块设计是一种动态冗余技术。

基本思想：

设置主模块和备用模块，通过验收测试判断执行结果。

流程：

``` text
主模块执行

↓

验收测试

↓

结果正确

↓

输出结果
```

如果失败：

``` text
主模块失败

↓

切换备用模块

↓

重新执行
```

------------------------------------------------------------------------

## 恢复块特点

优点：

-   节省资源；
-   支持错误恢复。

缺点：

-   需要设计验收测试；
-   切换过程增加复杂度。

------------------------------------------------------------------------

# 8. 防式程序设计

防式程序设计是一种提高程序可靠性的设计方法。

主要思想：

通过程序自身检查和保护机制，避免错误扩大。

主要措施：

-   参数检查；
-   状态检查；
-   异常处理；
-   错误恢复。

------------------------------------------------------------------------

# 9. 可靠性设计方法对比

  方法            核心思想
  --------------- ----------------
  容错设计        出错后继续运行
  检错设计        发现错误
  冗余设计        增加备用资源
  N版本程序设计   多版本表决
  恢复块设计      主备切换恢复
  防式程序设计    主动预防错误

# 11. 易错点

  易错知识                    正确理解
  --------------------------- ----------------------------
  容错就是避免错误            容错是在错误发生后继续运行
  检错可以自动恢复            检错主要负责发现问题
  N版本程序设计只有一个程序   多个独立版本
  恢复块同时执行多个版本      主模块失败后切换备用模块
