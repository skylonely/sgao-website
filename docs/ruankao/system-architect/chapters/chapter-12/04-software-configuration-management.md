# 1. 软件配置管理概述

软件配置管理（Software Configuration
Management，SCM）是软件项目管理的重要组成部分。

其主要目标是：

-   管理软件产品及相关文档的变化
-   保证配置项完整性
-   保证软件开发过程可追踪

软件配置管理主要解决：

-   软件版本变化
-   配置项控制
-   变更管理

------------------------------------------------------------------------

# 2. 配置项（Configuration Item）

配置项是软件配置管理中受控制的对象。

常见配置项包括：

-   源代码
-   软件文档
-   设计文档
-   测试文档
-   数据文件
-   软件工具

配置项需要进行：

-   标识
-   管理
-   控制
-   审计

------------------------------------------------------------------------

# 3. 配置管理计划

配置管理计划用于规定项目配置管理活动。

主要内容包括：

-   配置管理目标
-   配置管理范围
-   配置项定义
-   配置控制流程
-   配置审计要求

------------------------------------------------------------------------

# 4. 配置标识

配置标识用于确定需要进行配置管理的对象。

主要工作：

-   识别配置项
-   建立配置基线
-   确定配置结构

------------------------------------------------------------------------

# 5. 配置控制

配置控制用于管理配置项的变化。

主要过程：

``` text
提出变更

↓

变更评审

↓

批准变更

↓

实施变更

↓

记录变更
```

------------------------------------------------------------------------

# 6. 配置状态报告

配置状态报告用于记录和报告配置项当前状态。

主要内容：

-   配置项状态
-   变更记录
-   版本信息
-   配置活动记录

------------------------------------------------------------------------

# 7. 配置审计

配置审计用于检查配置管理活动是否符合要求。

主要目的：

-   验证配置完整性
-   检查配置一致性
-   确认变更是否正确执行

------------------------------------------------------------------------

# 8. 配置库

配置库用于保存和管理配置项。

主要包括：

-   开发库
-   受控库
-   产品库

用于支持：

-   版本管理
-   变更管理
-   软件发布

------------------------------------------------------------------------

# 9. 版本管理

版本管理用于记录软件产品不同版本之间的关系。

主要内容：

-   版本标识
-   版本控制
-   版本发布

配置项状态通常包括：

``` text
草稿

↓

正式

↓

修改
```

------------------------------------------------------------------------

# 10. CCB 配置控制委员会

CCB（Configuration Control Board）负责配置变更的评审和决策。

主要职责：

-   审批重大变更
-   控制配置变化
-   保证变更合理性

# 12. 易错点

  易混知识               区别
  ---------------------- ----------------------------
  配置项 vs 版本         管理对象；对象的不同状态
  配置控制 vs 配置审计   管理变化；检查正确性
  开发库 vs 产品库       开发过程使用；最终产品存放
