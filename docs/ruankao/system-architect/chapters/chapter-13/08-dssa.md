# 1. DSSA 概述

DSSA（Domain Specific Software Architecture）即特定领域软件架构。

DSSA
是针对某一特定应用领域，通过总结领域内系统的共同特征和变化规律，形成可复用的软件架构。

核心思想：

> 面向某一领域进行架构抽象，提高软件复用能力。

------------------------------------------------------------------------

# 2. 领域工程

DSSA 属于领域工程的重要内容。

领域工程关注：

-   分析某个领域的共同需求
-   提取领域中的通用功能
-   建立领域模型
-   设计可复用架构

领域工程的目标：

-   提高软件复用程度
-   降低重复开发成本
-   提高开发效率

------------------------------------------------------------------------

# 3. DSSA 基本思想

DSSA 不针对单个软件系统设计，而是面向一类软件系统。

主要过程：

``` text
多个相似系统

↓

提取共同特征

↓

形成领域模型

↓

设计领域架构

↓

支持多个系统开发
```

------------------------------------------------------------------------

# 4. DSSA 三个阶段

DSSA 主要包括三个阶段：

``` text
领域分析

↓

领域设计

↓

领域实现
```

------------------------------------------------------------------------

# 5. 领域分析

领域分析用于识别领域中的共同需求和变化部分。

主要任务：

-   确定领域范围
-   分析领域需求
-   提取领域特征
-   建立领域模型

输出：

-   领域模型
-   领域需求描述

------------------------------------------------------------------------

# 6. 领域设计

领域设计是在领域分析基础上设计领域架构。

主要任务：

-   确定领域架构
-   设计领域构件
-   定义构件之间关系

输出：

-   DSSA 架构
-   可复用构件设计

------------------------------------------------------------------------

# 7. 领域实现

领域实现用于根据领域设计实现具体的软件资产。

主要内容：

-   开发可复用构件
-   实现领域框架
-   支持具体系统开发

输出：

-   软件构件
-   应用系统

------------------------------------------------------------------------

# 8. DSSA 特点

DSSA 具有以下特点：

## 8.1 面向领域

针对特定领域进行分析和设计。

------------------------------------------------------------------------

## 8.2 支持复用

通过领域模型和架构提高软件复用能力。

------------------------------------------------------------------------

## 8.3 提高开发效率

减少重复设计和开发工作。

------------------------------------------------------------------------

# 9. DSSA 与普通软件开发对比

  对比项     DSSA       普通软件开发
  ---------- ---------- --------------
  目标       一类系统   单个系统
  关注点     领域共性   项目需求
  复用程度   高         较低
  输出       领域架构   应用系统

# 11. 易错点

  易混知识               区别
  ---------------------- ----------------------------
  DSSA vs 普通架构设计   面向领域；面向单个系统
  领域分析 vs 领域设计   提取需求特征；设计领域架构
  构件复用 vs DSSA       单个构件复用；领域级复用
