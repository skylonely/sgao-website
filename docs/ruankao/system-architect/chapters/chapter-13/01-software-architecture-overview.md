# 1. 软件架构概述

软件架构是软件系统设计的重要基础，用于描述软件系统的整体结构、组成元素以及元素之间的关系。

软件架构关注系统：

-   结构组织方式
-   组成元素
-   元素之间交互关系
-   设计约束

软件架构设计决定了软件系统的整体质量和后续演化能力。

------------------------------------------------------------------------

# 2. 软件架构定义

软件架构可以理解为：

> 软件系统的高层结构以及该结构中的元素、元素之间关系和约束。

软件架构主要描述：

-   系统由哪些部分组成
-   各部分如何协作
-   系统如何满足质量要求

------------------------------------------------------------------------

# 3. 软件架构组成

软件架构主要包括：

## 3.1 架构元素

架构元素是组成软件系统的基本单元。

包括：

-   模块
-   子系统
-   构件
-   服务

------------------------------------------------------------------------

## 3.2 元素之间关系

描述不同架构元素之间如何协作。

常见关系：

-   调用关系
-   依赖关系
-   通信关系
-   数据流关系

------------------------------------------------------------------------

## 3.3 架构约束

用于限制系统设计方式。

例如：

-   技术限制
-   平台限制
-   性能要求
-   安全要求

------------------------------------------------------------------------

# 4. 软件架构的重要性

软件架构的重要作用：

## 4.1 指导系统设计

架构为详细设计和开发提供整体方向。

------------------------------------------------------------------------

## 4.2 保证系统质量

合理的软件架构有助于提高：

-   性能
-   可维护性
-   可扩展性
-   可靠性

------------------------------------------------------------------------

## 4.3 支持系统演化

良好的架构能够降低系统修改成本，提高系统适应变化的能力。

------------------------------------------------------------------------

# 5. 软件架构与软件生命周期

软件架构贯穿软件生命周期。

主要影响阶段：

``` text
需求分析

↓

架构设计

↓

详细设计

↓

实现

↓

测试

↓

维护演化
```

架构设计需要根据：

-   功能需求
-   非功能需求
-   技术环境

进行综合考虑。

------------------------------------------------------------------------

# 6. 软件架构设计关注点

软件架构设计需要重点考虑：

## 功能需求

系统需要完成的业务功能。

------------------------------------------------------------------------

## 非功能需求

包括：

-   性能
-   安全性
-   可用性
-   可修改性
-   可扩展性

------------------------------------------------------------------------

## 技术约束

包括：

-   开发平台
-   技术框架
-   部署环境

------------------------------------------------------------------------

# 7. 构件（Component）

构件是软件架构中的重要组成部分。

构件通常具有：

-   明确接口
-   独立功能
-   可复用能力

构件之间通过接口进行交互。

构件化设计可以提高：

-   软件复用性
-   系统可维护性
-   开发效率

------------------------------------------------------------------------

# 9. 易错点

  易混知识                 区别
  ------------------------ ----------------------------
  架构 vs 详细设计         整体结构；具体实现
  功能需求 vs 非功能需求   做什么；做到什么程度
  模块 vs 构件             功能划分；可部署可复用单元
