# 08 Exercises（章节练习）

> 本文依据《15.软件架构的演化和维护.pdf》整理，用于系统架构设计师考试复习。

------------------------------------------------------------------------

# 一、基础练习

## 1. 软件架构演化的主要目的

A. 删除旧系统\
B. 适应环境变化和新的业务需求\
C. 停止系统维护\
D. 替代全部技术

答案：

``` text
B
```

------------------------------------------------------------------------

# 二、面向对象架构演化

## 2. AO 表示

``` text
Add Object（增加对象）
```

## 3. DO 表示

``` text
Delete Object（删除对象）
```

## 4. 消息演化包括

-   AM（Add Message）
-   DM（Delete Message）
-   SMO（Swap Message Order）
-   OM（Overturn Message）
-   CMM（Change Message Module）

------------------------------------------------------------------------

# 三、架构演化方式

软件架构演化方式：

-   基于过程和函数的演化
-   面向对象演化
-   基于组件演化
-   基于架构演化

静态演化：

-   运行前完成；
-   通常需要重新部署。

动态演化：

-   运行过程中完成；
-   可以不中断服务。

------------------------------------------------------------------------

# 四、架构演化原则

重点：

-   成本可控；
-   风险可控；
-   平滑演化；
-   模块独立演化；
-   影响可控；
-   复杂性可控。

------------------------------------------------------------------------

# 五、大型网站架构演化

典型过程：

``` text
单体架构

↓

垂直架构

↓

缓存/CDN

↓

反向代理

↓

负载均衡

↓

分布式服务
```

CDN主要作用：

``` text
提高静态资源访问速度，降低源站压力
```

------------------------------------------------------------------------

# 六、架构维护

主要内容：

-   架构知识管理；
-   架构修改管理；
-   架构版本管理。

版本管理作用：

-   保存架构历史；
-   支持版本比较；
-   保证演化可追踪。

------------------------------------------------------------------------

# 七、综合分析题

某网站从单体架构发展到分布式服务架构，原因：

-   用户规模增加；
-   数据量增长；
-   业务复杂度提高；
-   需要更好的扩展能力。
