# 二、软件架构演化总结

## 1. 软件架构演化定义

软件架构演化是：

> 对软件架构进行修改和完善，使软件能够适应环境变化和新的业务需求。

架构演化不是简单修改代码，而是针对：

-   架构元素；
-   架构关系；
-   架构约束；
-   质量属性；

进行调整。

------------------------------------------------------------------------

## 2. 架构演化原因

主要包括：

### 业务需求变化

-   新功能增加；
-   业务流程调整。

### 技术环境变化

-   新技术引入；
-   平台变化。

### 系统规模变化

-   用户增长；
-   数据增长；
-   并发提高。

### 运行环境变化

-   部署环境变化；
-   外部条件变化。

# 四、软件架构演化方式总结

## 按实现方式分类

包括：

1.  基于过程和函数的演化；
2.  面向对象演化；
3.  基于组件演化；
4.  基于架构演化。

------------------------------------------------------------------------

## 按演化时机分类

### 静态演化

特点：

-   运行前完成；
-   通常需要重新部署。

------------------------------------------------------------------------

### 动态演化

特点：

-   运行过程中完成；
-   可以不中断系统。

动态演化层次：

``` text
交互动态性

↓

结构动态性

↓

架构动态性
```

# 五、软件架构演化原则总结

重点原则：

## 1. 成本控制原则

控制演化成本。

## 2. 风险可控原则

降低架构修改风险。

## 3. 平滑演化原则

保证系统逐步变化。

## 4. 模块独立演化原则

降低模块之间影响。

## 5. 影响可控原则

控制变化传播范围。

## 6. 复杂性可控原则

避免系统越来越复杂。

其他原则：

-   目标一致原则；
-   有利于重构原则；
-   有利于重用原则；
-   适应新技术原则；
-   适应新需求原则。

------------------------------------------------------------------------

# 六、软件架构演化评估总结

## 演化过程已知

特点：

-   可以追踪历史变化；
-   可以分析每次修改影响。

方法：

-   架构度量；
-   影响分析。

------------------------------------------------------------------------

## 演化过程未知

特点：

-   不清楚历史过程；
-   根据当前架构状态评价。

重点：

-   当前结构；
-   质量属性。

------------------------------------------------------------------------

# 十二、本章总结

软件架构的演化和维护是系统架构设计师考试中的重要章节。

学习重点：

-   理解为什么需要架构演化；
-   掌握不同架构演化方式；
-   熟悉大型网站架构演进规律；
-   理解架构维护管理方法。

核心思想：

> 软件架构不是一次设计完成，而是在业务、技术和环境变化中持续演化和维护。
