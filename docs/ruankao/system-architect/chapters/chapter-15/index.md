# 第十五章 软件架构的演化和维护

> 本章依据《15.软件架构的演化和维护.pdf》整理，用于系统架构设计师考试复习。

------------------------------------------------------------------------

# 一、章节概述

软件架构演化和维护研究如何让软件系统架构适应业务变化和环境变化。

软件架构演化是指：

> 对软件架构进行修改和完善，使软件能够适应环境变化和新的业务需求。

架构演化贯穿软件生命周期：

``` text
需求获取

↓

软件架构建模

↓

软件架构文档

↓

软件架构实现

↓

软件架构维护
```


------------------------------------------------------------------------

# 二、软件架构演化内容

## 1. 软件架构演化定义

主要内容：

-   架构修改与完善；
-   适应业务变化；
-   降低软件维护成本；
-   提高系统可扩展性。

------------------------------------------------------------------------

## 2. 面向对象软件架构演化

主要包括：

### 对象演化

-   Add Object（AO）
-   Delete Object（DO）

### 消息演化

-   Add Message（AM）
-   Delete Message（DM）
-   Swap Message Order（SMO）
-   Overturn Message（OM）
-   Change Message Module（CMM）

### 复合片段演化

-   Add Fragment（AF）
-   Delete Fragment（DF）
-   Fragment Type Change（FTC）
-   Fragment Condition Change（FCC）

### 约束演化

-   Add Constraint（AC）
-   Delete Constraint（DC）


------------------------------------------------------------------------

# 三、软件架构演化方式分类

## 按实现方式和实施粒度

包括：

-   基于过程和函数的演化；
-   面向对象演化；
-   基于组件演化；
-   基于架构演化。

------------------------------------------------------------------------

## 按演化时机

### 静态演化

特点：

-   设计阶段进行；
-   运行前完成。

### 动态演化

特点：

-   系统运行期间进行；
-   可以不中断系统服务。

# 五、软件架构演化评估

主要分为：

## 演化过程已知的评估

特点：

-   可以分析每一次架构变化；
-   可以度量演化影响。

## 演化过程未知的评估

特点：

-   根据演化后的架构结果；
-   分析架构质量属性变化。

# 七、软件架构维护

主要包括：

## 架构知识管理

作用：

-   保存架构设计决策；
-   记录架构演化原因。

## 架构修改管理

重点：

-   控制修改影响范围；
-   降低系统维护风险。

## 架构版本管理

作用：

-   支撑架构演化控制；
-   保证版本可追踪。
