# 1. 分布式系统案例概述

分布式系统主要用于解决：

-   单机性能不足；
-   数据规模增长；
-   高并发访问；
-   高可靠要求。

典型架构：

``` text
客户端

↓

负载均衡

↓

应用服务器集群

↓

分布式服务

↓

数据库集群
```

------------------------------------------------------------------------

# 2. 分布式系统基本概念（★★★★★）

分布式系统：

> 多个独立计算节点通过网络协同完成任务的系统。

特点：

-   多节点协作；
-   资源共享；
-   并发处理；
-   故障不可避免。

------------------------------------------------------------------------

# 3. 分布式系统特点（★★★★★）

## 分布性

计算资源分布在多个节点。

------------------------------------------------------------------------

## 并发性

多个节点同时执行任务。

------------------------------------------------------------------------

## 透明性

隐藏底层分布细节。

------------------------------------------------------------------------

## 容错性

部分节点故障时系统仍可运行。

------------------------------------------------------------------------

# 4. CAP理论案例（★★★★★）

CAP包括：

  名称   含义
  ------ --------------------------------
  C      Consistency 一致性
  A      Availability 可用性
  P      Partition Tolerance 分区容错性

CAP理论：

> 分布式系统无法同时满足一致性、可用性和分区容错性，只能重点保证其中两个。

------------------------------------------------------------------------

## 案例分析

网络发生分区：

选择一致性：

> 保证数据一致，但部分请求可能失败。

选择可用性：

> 保证系统响应，但允许短暂数据不一致。

------------------------------------------------------------------------

# 5. BASE模型案例（★★★★★）

BASE：

-   Basically Available（基本可用）
-   Soft State（软状态）
-   Eventually Consistent（最终一致性）

核心思想：

> 通过牺牲强一致性，提高系统可用性和扩展能力。

应用：

-   电商系统；
-   秒杀系统；
-   大规模互联网系统。

------------------------------------------------------------------------

# 6. 分布式一致性案例（★★★★★）

分布式一致性：

保证多个节点中的数据状态一致。

常见策略：

-   强一致性；
-   弱一致性；
-   最终一致性。

选择原则：

根据业务重要程度决定一致性级别。

------------------------------------------------------------------------

# 7. 分布式事务案例（★★★★★）

问题：

一个业务操作涉及多个服务。

例如：

``` text
订单服务

↓

库存服务

↓

支付服务
```

需要保证：

-   全部成功；
-   或全部失败。

------------------------------------------------------------------------

# 8. 两阶段提交2PC案例

2PC：

Two Phase Commit。

流程：

``` text
准备阶段

↓

提交阶段
```

------------------------------------------------------------------------

## 优点

-   强一致性；
-   事务控制简单。

------------------------------------------------------------------------

## 缺点

-   性能较低；
-   存在阻塞问题。

------------------------------------------------------------------------

# 9. TCC事务案例（★★★★★）

TCC：

-   Try；
-   Confirm；
-   Cancel。

思想：

通过业务补偿实现最终一致性。

适用于：

-   分布式业务流程；
-   高并发交易系统。

------------------------------------------------------------------------

# 10. 消息队列案例（★★★★★）

消息队列作用：

-   异步处理；
-   系统解耦；
-   流量削峰。

结构：

``` text
生产者

↓

消息队列

↓

消费者
```

------------------------------------------------------------------------

## 应用场景

### 秒杀系统

将大量请求放入消息队列，保护后端服务。

------------------------------------------------------------------------

### 异步任务

提高系统响应速度。

------------------------------------------------------------------------

# 11. 分布式缓存案例（★★★★★）

常见：

-   Redis；
-   分布式缓存集群。

作用：

-   降低数据库压力；
-   提升访问速度。

------------------------------------------------------------------------

## 常见问题

### 缓存穿透

大量请求访问不存在的数据。

------------------------------------------------------------------------

### 缓存击穿

热点数据失效导致大量请求访问数据库。

------------------------------------------------------------------------

### 缓存雪崩

大量缓存同时失效。

------------------------------------------------------------------------

# 12. 分布式锁案例

目的：

保证多个节点之间：

> 同一时间只有一个节点执行关键操作。

实现方式：

-   Redis分布式锁；
-   数据库锁；
-   Zookeeper锁。

应用：

-   库存扣减；
-   定时任务；
-   秒杀控制。

# 15. 案例分析答题模板

## 高并发访问

> 采用分布式架构，通过负载均衡、服务器集群和缓存机制提高系统吞吐能力。

------------------------------------------------------------------------

## 数据一致性

> 根据业务需求选择合适的一致性策略，对于非核心业务采用最终一致性，提高系统可用性。

------------------------------------------------------------------------

## 服务解耦

> 引入消息队列，实现异步通信和流量削峰，降低系统耦合。

------------------------------------------------------------------------

## 分布式事务

> 根据业务特点选择2PC、TCC或最终一致性方案，保证跨服务业务操作的一致性。

------------------------------------------------------------------------

# 19. 本节小结

分布式系统案例核心：

> 根据系统规模、性能和可靠性需求，合理设计分布式架构，并在一致性、可用性和性能之间进行权衡。

案例分析重点：

-   判断是否需要分布式架构；
-   根据业务选择一致性方案；
-   使用消息队列、缓存、事务机制解决分布式问题；
-   结合高可用设计保证系统稳定运行。
