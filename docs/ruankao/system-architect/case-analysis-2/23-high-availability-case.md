# 1. 高可用系统案例概述

高可用（High Availability）主要解决：

-   系统故障；
-   服务中断；
-   数据丢失；
-   灾难恢复。

目标：

> 保证系统持续、稳定地提供服务。

典型架构：

``` text
用户请求

↓

负载均衡

↓

服务器集群

↓

数据库高可用

↓

备份系统
```

------------------------------------------------------------------------

# 2. 高可用基本概念（★★★★★）

高可用关注：

-   Availability（可用性）
-   Reliability（可靠性）
-   Maintainability（可维护性）

核心目标：

减少：

-   故障时间；
-   服务中断。

------------------------------------------------------------------------

# 3. SLA服务等级协议案例（★★★★★）

SLA：

Service Level Agreement。

用于描述：

-   服务可用率；
-   响应时间；
-   故障恢复时间。

例如：

99.9%可用性：

一年允许故障时间约：

``` text
8小时46分钟
```

------------------------------------------------------------------------

# 4. 可用性指标计算案例（★★★★★）

公式：

``` text
可用性 = 正常运行时间 / 总时间 × 100%
```

例如：

系统运行10000小时：

故障10小时：

``` text
9990 / 10000 = 99.9%
```

------------------------------------------------------------------------

# 5. 集群架构案例（★★★★★）

集群：

> 多个服务器共同提供服务。

结构：

``` text
用户

↓

负载均衡

↓

服务器1
服务器2
服务器3
```

优势：

-   提升处理能力；
-   避免单点故障。

------------------------------------------------------------------------

# 6. 负载均衡高可用案例

负载均衡作用：

-   分散请求压力；
-   提高系统吞吐；
-   避免单节点故障。

常见方式：

-   软件负载均衡；
-   硬件负载均衡。

------------------------------------------------------------------------

# 7. 主备架构案例（★★★★★）

主备模式：

``` text
Primary

↓

```

特点：

-   主节点提供服务；
-   备用节点等待接管。

适用于：

-   数据库系统；
-   核心业务系统。

------------------------------------------------------------------------

# 11. RTO与RPO案例（★★★★★）

## RTO

Recovery Time Objective。

恢复时间目标：

> 系统需要多久恢复服务。

------------------------------------------------------------------------

## RPO

Recovery Point Objective。

恢复点目标：

> 可以接受丢失多少数据。

------------------------------------------------------------------------

案例：

RTO：

30分钟。

RPO：

5分钟。

表示：

-   30分钟内恢复系统；
-   最多丢失5分钟数据。

------------------------------------------------------------------------

# 12. 双活架构案例（★★★★★）

双活：

两个数据中心同时提供服务。

结构：

``` text
用户

↓

中心A

中心B
```

优势：

-   资源利用率高；
-   故障切换快。

挑战：

-   数据一致性；
-   数据同步。

------------------------------------------------------------------------

# 13. 多活架构案例

多活：

优势：

-   支撑大规模访问；
-   提升容灾能力。

挑战：

-   数据同步；
-   一致性控制。

# 15. 案例分析答题模板（★★★★★）

## 系统不能中断

> 采用集群部署和负载均衡技术，避免单点故障，提高系统可用性。

------------------------------------------------------------------------

## 数据不能丢失

> 采用数据复制、备份和灾难恢复机制，提高数据可靠性。

------------------------------------------------------------------------

## 故障自动恢复

> 采用健康检查和故障转移机制，实现自动切换，提高系统连续服务能力。

------------------------------------------------------------------------

## 灾难场景

> 建立异地灾备中心，通过数据同步和快速恢复机制保证业务连续性。

# 17. 易错点

  易错知识               正确理解
  ---------------------- ------------------------
  高可用就是高性能       高可用关注持续服务能力
  集群一定没有故障       集群降低单点风险
  备份等于灾备           灾备还包括恢复能力
  双活一定没有数据问题   双活需要解决一致性问题

# 19. 本节小结

高可用系统案例核心：

> 通过集群、故障转移、数据复制和灾难恢复等技术，保证系统持续稳定运行。

案例分析重点：

-   根据业务连续性要求设计架构；
-   明确SLA、RTO、RPO指标；
-   结合集群、备份、灾备方案提高系统可靠性；
-   平衡成本、性能和可用性。
