# 1. 数据库优化案例概述

数据库常见问题：

-   查询响应慢；
-   并发访问压力大；
-   数据量持续增长；
-   数据库成为系统瓶颈。

优化目标：

-   提升查询效率；
-   降低数据库压力；
-   提高系统吞吐能力。

------------------------------------------------------------------------

# 2. 数据库性能瓶颈分析（★★★★★）

常见瓶颈：

## CPU瓶颈

原因：

-   复杂SQL计算；
-   大量排序；
-   聚合操作。

------------------------------------------------------------------------

## IO瓶颈

原因：

-   全表扫描；
-   数据量过大；
-   磁盘访问频繁。

------------------------------------------------------------------------

## 锁竞争

原因：

-   高并发更新；
-   长事务；
-   锁范围过大。

------------------------------------------------------------------------

# 3. 数据库索引优化案例（★★★★★）

索引：

> 用于提高数据库查询效率的数据结构。

查询过程：

``` text
查询请求

↓

索引定位

↓

访问数据

↓

返回结果
```

------------------------------------------------------------------------

## 索引优化原则

-   为高频查询字段建立索引；
-   合理使用联合索引；
-   避免建立过多索引。

------------------------------------------------------------------------

## 索引问题

索引过多会：

-   增加存储空间；
-   降低写入性能。

------------------------------------------------------------------------

# 6. 数据库分区案例

分区：

> 将大型数据表划分为多个逻辑区域。

优势：

-   提升查询效率；
-   方便数据管理。

常见方式：

-   范围分区；
-   哈希分区；
-   列表分区。

------------------------------------------------------------------------

# 7. 分库分表案例（★★★★★）

解决：

> 单数据库数据量过大和并发压力问题。

------------------------------------------------------------------------

## 垂直拆分

按照业务拆分：

``` text
用户库

订单库

商品库
```

优势：

-   降低单库压力；
-   提高业务隔离。

------------------------------------------------------------------------

## 水平拆分

按照数据规则拆分：

``` text
订单表1

订单表2

订单表3
```

优势：

-   扩展数据容量；
-   提高并发能力。

------------------------------------------------------------------------

# 8. 读写分离案例（★★★★★）

架构：

``` text
写请求

↓

主数据库


读请求

↓

从数据库
```

优势：

-   分散数据库压力；
-   提升查询能力。

适用：

读多写少业务。

------------------------------------------------------------------------

# 11. 数据库连接池案例

``` text
↓

```

优势：

-   连接复用；
-   降低连接创建成本；

# 16. 案例分析答题模板（★★★★★）

## 数据查询慢

> 通过SQL优化、建立合理索引、优化查询执行计划，提高数据库查询效率。

------------------------------------------------------------------------

## 数据量快速增长

> 采用分库分表方案，对数据进行水平或垂直拆分，提高数据库扩展能力。

------------------------------------------------------------------------

## 数据库压力过大

> 采用读写分离架构，将读请求分散到从数据库，降低主数据库压力。

------------------------------------------------------------------------

## 高可用要求

> 采用主从复制、故障检测和自动切换机制，提高数据库系统可用性。

# 18. 易错点

  易错知识               正确理解
  ---------------------- ------------------
  建索引越多越好         索引会影响写性能
  分库分表解决所有问题   会增加系统复杂度
  读写分离保证一致性     主要提升读性能
  数据库优化只优化SQL    需要综合架构优化
