# 1. 分布式缓存案例概述

缓存主要用于解决：

-   数据库访问压力过大；
-   系统响应速度慢；
-   高并发访问问题。

典型架构：

``` text
用户请求

↓

应用服务器

↓

缓存系统

↓

数据库
```

核心目标：

-   提升访问速度；
-   降低数据库压力；
-   提高系统吞吐能力。

------------------------------------------------------------------------

# 2. 缓存基本概念（★★★★★）

缓存：

> 将访问频率高的数据存储在高速存储介质中，减少对后端数据源的访问。

特点：

-   访问速度快；
-   减少数据库压力；
-   提高系统性能。

# 6. 缓存更新策略案例（★★★★★）

常见策略：

## Cache Aside模式

流程：

读取：

``` text
查询缓存

↓

缓存不存在

↓

查询数据库

↓

写入缓存
```

更新：

``` text
更新数据库

↓

删除缓存
```

------------------------------------------------------------------------

## 定时刷新

适用于：

变化较少的数据。

------------------------------------------------------------------------

## 主动更新

业务变化时主动同步缓存。

------------------------------------------------------------------------

# 7. 缓存一致性案例（★★★★★）

问题：

数据库和缓存数据可能不一致。

例如：

``` text
数据库数据更新

↓

缓存仍保存旧数据
```

解决：

-   更新数据库后删除缓存；
-   设置缓存过期时间；
-   消息通知同步。

------------------------------------------------------------------------

# 8. 缓存穿透案例（★★★★★）

定义：

大量请求访问不存在的数据。

结果：

请求直接访问数据库。

解决：

-   缓存空对象；
-   布隆过滤器；
-   参数校验。

------------------------------------------------------------------------

# 9. 缓存击穿案例（★★★★★）

定义：

热点数据失效，大量请求同时访问数据库。

解决：

-   热点数据永不过期；
-   互斥锁；
-   提前刷新。

------------------------------------------------------------------------

# 10. 缓存雪崩案例（★★★★★）

定义：

大量缓存同时失效。

影响：

数据库压力瞬间增加。

解决：

-   设置随机过期时间；
-   多级缓存；
-   限流保护。

------------------------------------------------------------------------

# 14. 缓存架构案例分析

## 案例一：数据库压力过大

问题：

大量查询直接访问数据库。

方案：

> 引入分布式缓存，将热点数据存储在缓存系统中，减少数据库访问，提高系统性能。

------------------------------------------------------------------------

## 案例二：高并发访问热点数据

问题：

大量用户同时访问相同数据。

方案：

> 采用Redis缓存热点数据，并结合限流和热点保护机制，提高系统承载能力。

------------------------------------------------------------------------

## 案例三：缓存和数据库数据不一致

问题：

缓存数据与数据库状态不同步。

方案：

> 采用合理的缓存更新策略，例如更新数据库后删除缓存，并结合过期机制保证最终一致性。

------------------------------------------------------------------------

# 15. 案例分析答题模板（★★★★★）

## 性能优化

> 采用分布式缓存存储热点数据，减少数据库访问压力，提高系统响应速度和吞吐能力。

------------------------------------------------------------------------

## 高并发设计

> 通过缓存、限流和热点数据保护机制，降低后端服务压力，提高系统稳定性。

------------------------------------------------------------------------

## 数据一致性

> 采用缓存更新策略和过期机制，保证缓存与数据库之间的最终一致性。

# 17. 易错点

  易错知识               正确理解
  ---------------------- ------------------------
  缓存可以替代数据库     缓存只是性能优化手段
  删除缓存一定保证一致   需要结合更新策略
  缓存越多越好           会增加一致性复杂度
  Redis只能做缓存        也可用于锁、队列等场景
