# 1. 消息队列案例概述

消息队列主要用于解决：

-   系统耦合问题；
-   高并发压力；
-   异步处理需求；
-   流量突增问题。

典型结构：

``` text
生产者

↓

消息队列

↓

消费者
```

------------------------------------------------------------------------

# 2. 消息队列基本概念（★★★★★）

消息队列：

> 通过消息传递实现系统之间异步通信的一种中间件。

主要角色：

-   Producer：消息生产者；
-   Message Queue：消息存储；
-   Consumer：消息消费者。

------------------------------------------------------------------------

# 3. 同步架构与异步架构对比（★★★★★）

## 同步调用

``` text
用户请求

↓

服务A

↓

服务B

↓

返回结果
```

特点：

-   调用链长；
-   响应时间增加；
-   服务耦合较高。

------------------------------------------------------------------------

## 异步调用

``` text
用户请求

↓

服务A

↓

消息队列

↓

后台消费者处理
```

优势：

-   提高响应速度；
-   降低系统压力；
-   提升系统扩展能力。

------------------------------------------------------------------------

# 5. 消息队列核心作用（★★★★★）

## 5.1 系统解耦

生产者无需直接依赖消费者。

例如：

``` text
订单服务

↓

消息队列

↓

库存服务

物流服务

通知服务
```

优势：

-   降低系统耦合；
-   提高扩展能力。

------------------------------------------------------------------------

## 5.2 异步处理

适用于：

-   邮件发送；
-   短信通知；
-   文件处理；
-   日志处理。

------------------------------------------------------------------------

## 5.3 流量削峰

典型场景：

秒杀系统。

``` text
大量请求

↓

消息队列缓存

↓

后台消费者处理
```

作用：

保护后端系统，避免瞬时压力过大。

------------------------------------------------------------------------

# 6. 消息可靠性设计（★★★★★）

消息可靠性主要解决：

-   消息不丢失；
-   消息不重复；
-   消息可恢复。

------------------------------------------------------------------------

## 消息持久化

保证消息不会因为服务异常丢失。

------------------------------------------------------------------------

## ACK确认机制

消费者处理成功后确认消息。

------------------------------------------------------------------------

## 失败重试

处理失败后重新消费。

------------------------------------------------------------------------

# 7. 消息重复消费案例

原因：

-   消费失败重试；
-   网络异常；
-   ACK确认失败。

解决：

采用幂等设计：

> 同一消息被多次处理，最终结果保持一致。

常见方法：

-   唯一消息ID；
-   去重表；
-   状态判断。

------------------------------------------------------------------------

# 8. 消息顺序性案例

问题：

部分业务要求消息顺序。

例如：

``` text
创建订单

↓

支付订单

↓

完成订单
```

解决：

-   单队列顺序消费；
-   分区顺序；
-   消费端控制顺序。

------------------------------------------------------------------------

# 9. 消息积压案例

原因：

-   消费者处理能力不足；
-   消费服务异常；
-   流量突然增加。

解决：

-   增加消费者数量；
-   提升消费速度；
-   优化业务处理逻辑。

------------------------------------------------------------------------

# 10. Kafka架构案例（★★★★★）

Kafka适用于：

-   高吞吐消息处理；
-   大规模日志处理；
-   流式数据处理。

核心结构：

``` text
Producer

↓

Topic

↓

Partition

↓

Consumer
```

核心概念：

-   Topic：消息主题；
-   Partition：分区；
-   Consumer Group：消费者组。

# 11. RabbitMQ架构案例（★★★★★）

RabbitMQ特点：

-   消息可靠性高；
-   支持复杂路由。

结构：

``` text
Producer

↓

Exchange

↓

Queue

↓

Consumer
```

核心：

-   Exchange负责消息路由；
-   Queue保存消息；
-   Consumer消费消息。
