# 1. 安全模型案例概述

安全模型用于描述：

-   系统安全目标；
-   主体和客体之间的访问关系；
-   信息流动规则。

案例主要考查：

-   保密性；
-   完整性；
-   访问控制；
-   权限管理。

分析流程：

``` text
安全需求

↓

确定保护目标

↓

选择安全模型

↓

设计访问控制策略
```

------------------------------------------------------------------------

# 2. 信息安全模型基础（★★★★★）

安全模型主要包含：

## 主体 Subject

主动访问资源的实体。

例如：

-   用户；
-   进程。

------------------------------------------------------------------------

## 客体 Object

被访问的资源。

例如：

-   文件；
-   数据库；
-   信息资源。

------------------------------------------------------------------------

## 访问权限

描述主体对客体可以执行的操作。

例如：

-   读；
-   写；
-   修改。

------------------------------------------------------------------------

# 3. Bell-LaPadula安全模型案例（★★★★★）

Bell-LaPadula模型主要关注：

> 信息保密性。

适用于：

-   军事系统；
-   政府安全系统。

------------------------------------------------------------------------

## 核心规则

### 不上读（No Read Up）

低安全级别主体不能读取高安全级别数据。

示例：

``` text
普通用户

↓

禁止读取

↓

机密文件
```

------------------------------------------------------------------------

### 不下写（No Write Down）

高安全级别主体不能向低安全级别对象写入信息。

目的：

防止敏感信息泄露。

------------------------------------------------------------------------

## 案例分析

需求：

防止普通用户访问机密数据。

方案：

> 采用Bell-LaPadula模型，根据安全级别控制访问权限，保证信息保密性。

------------------------------------------------------------------------

# 4. Biba完整性模型案例（★★★★★）

Biba模型主要关注：

> 信息完整性。

目标：

防止数据被非法修改。

------------------------------------------------------------------------

## 核心规则

### 不下读（No Read Down）

高完整性主体不能读取低完整性数据。

------------------------------------------------------------------------

### 不上写（No Write Up）

低完整性主体不能修改高完整性数据。

------------------------------------------------------------------------

## 案例分析

需求：

防止普通用户修改核心业务数据。

方案：

> 采用Biba模型，通过完整性级别控制写入权限，保护数据正确性。

------------------------------------------------------------------------

# 5. Clark-Wilson完整性模型案例（★★★★★）

Clark-Wilson模型关注：

> 商业系统中的数据完整性。

常用于：

-   银行系统；
-   企业业务系统。

------------------------------------------------------------------------

核心思想：

通过：

-   事务；
-   权限分离；
-   完整性验证。

保证数据正确。

------------------------------------------------------------------------

主要机制：

## 受控数据项

限制数据直接修改。

------------------------------------------------------------------------

## 转换程序

通过合法程序修改数据。

------------------------------------------------------------------------

## 权限分离

避免单个人员完成全部关键操作。

------------------------------------------------------------------------

# 6. 信息流控制模型案例

信息流控制：

关注：

> 信息是否按照规定方向流动。

目标：

防止：

-   信息泄露；
-   非授权传播。

------------------------------------------------------------------------

案例：

高安全级别数据：

``` text
高等级

↓

禁止流向

↓

低等级
```

``` text

↓

↓

↓
```

------------------------------------------------------------------------

## 身份认证

-   用户身份；

------------------------------------------------------------------------

-   用户操作；
-   安全事件。

# 10. 案例分析答题模板

## 场景：保护机密信息

答案：

> 采用Bell-LaPadula安全模型，通过安全级别控制访问权限，限制低级主体读取高级信息，保证数据保密性。

------------------------------------------------------------------------

## 场景：防止数据被非法修改

答案：

> 采用Biba完整性模型，通过完整性级别控制数据访问和修改权限，保证数据完整性。

------------------------------------------------------------------------

## 场景：企业业务数据保护

答案：

> 采用Clark-Wilson模型，通过事务处理、权限分离和完整性验证机制保证业务数据正确性。

# 14. 本节小结

安全模型案例核心：

> 根据系统保护目标选择合适的安全模型，通过访问控制规则保证信息安全。

案例分析重点：

-   保密性问题优先考虑 Bell-LaPadula；
-   完整性问题优先考虑 Biba；
-   商业数据正确性优先考虑 Clark-Wilson；
-   结合认证、授权、审计形成完整安全架构。
