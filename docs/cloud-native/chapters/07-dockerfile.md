# 1. Dockerfile概述

Dockerfile：

> 是用于自动构建 Docker
> 镜像的文本文件，通过描述镜像构建步骤，实现应用环境标准化。

关系：

``` text
Dockerfile

↓

docker build

↓

Docker Image

↓

docker run

↓

Container
```

Dockerfile解决：

-   环境一致性；
-   自动化部署；
-   镜像标准化管理。

# 3. Dockerfile基本结构

Dockerfile由多个指令组成。

示例：

``` dockerfile
FROM node:20

WORKDIR /app

COPY package.json .

RUN npm install

COPY . .

CMD ["npm","start"]
```

每条指令通常对应一个镜像Layer。

------------------------------------------------------------------------

# 4. Dockerfile常用指令

## FROM

指定基础镜像：

``` dockerfile
FROM nginx:latest
```

------------------------------------------------------------------------

## RUN

执行构建阶段命令：

``` dockerfile
RUN npm install
```

------------------------------------------------------------------------

## COPY

复制文件：

``` dockerfile
COPY ./app /app
```

------------------------------------------------------------------------

## ADD

复制文件并支持额外能力。

------------------------------------------------------------------------

## WORKDIR

设置工作目录：

``` dockerfile
WORKDIR /app
```

------------------------------------------------------------------------

## CMD

设置默认启动命令：

``` dockerfile
CMD ["npm","start"]
```

------------------------------------------------------------------------

## ENTRYPOINT

定义容器入口程序。

------------------------------------------------------------------------

## EXPOSE

声明服务端口：

``` dockerfile
EXPOSE 8080
```

------------------------------------------------------------------------

## ENV

设置环境变量：

``` dockerfile
ENV NODE_ENV=production
```

# 5. Dockerfile执行机制

Docker在执行Dockerfile时：

``` text
读取指令

↓

执行操作

↓

生成Layer

↓

合并形成Image
```

例如：

``` dockerfile
FROM nginx

COPY index.html /html

CMD nginx
```

形成：

``` text
CMD Layer

↓

COPY Layer

↓

Base Image Layer
```

# 7. 多阶段构建（Multi-stage Build）

## 问题

传统构建：

-   包含编译工具；
-   镜像体积大；
-   安全风险高。

------------------------------------------------------------------------

## 多阶段构建

流程：

``` text
Build Stage

↓

Compile

↓

Runtime Stage

↓

Production Image
```

示例：

``` dockerfile
FROM node AS build

RUN npm run build


FROM nginx

COPY --from=build dist /usr/share/nginx/html
```

优势：

-   减小镜像体积；
-   降低攻击面；
-   分离开发环境和运行环境。

------------------------------------------------------------------------

# 8. 镜像优化策略

## 使用轻量基础镜像

例如：

-   Alpine；
-   Distroless。

------------------------------------------------------------------------

## 减少镜像Layer

优化：

``` dockerfile
RUN apt update && apt install xxx
```

避免：

``` dockerfile
RUN apt update

RUN apt install xxx
```

------------------------------------------------------------------------

## 使用.dockerignore

避免复制：

-   node_modules；
-   日志；
-   临时文件。

------------------------------------------------------------------------

## 清理构建缓存

减少：

-   镜像大小；
-   无用文件。

------------------------------------------------------------------------

# 13. 常见问题与优化

## 镜像过大

原因：

-   基础镜像过大；
-   包含无用依赖。

解决：

-   多阶段构建；
-   使用轻量镜像。

------------------------------------------------------------------------

## 构建速度慢

解决：

-   合理利用缓存；
-   优化Layer顺序。

# 14. 常用构建命令

构建镜像：

``` bash
docker build -t app:v1 .
```

查看镜像：

``` bash
docker images
```

删除镜像：

``` bash
docker rmi app:v1
```

查看构建历史：

``` bash
docker history image
```

# 15. 系统架构设计师考点

## Dockerfile作用

答：

> Dockerfile通过文本化方式描述镜像构建过程，实现应用环境标准化和自动化部署。

------------------------------------------------------------------------

## 为什么采用多阶段构建？

答：

> 多阶段构建分离编译环境和运行环境，减少最终镜像大小，提高安全性。

------------------------------------------------------------------------

## 如何优化Docker镜像？

答：

> 使用轻量基础镜像、减少Layer数量、清理无用依赖、采用多阶段构建，提高镜像效率和安全性。
