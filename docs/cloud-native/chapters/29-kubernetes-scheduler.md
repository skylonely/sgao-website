# 1. Kubernetes调度概述

Scheduler：

> Kubernetes负责将未调度Pod分配到合适Node节点的控制组件。

核心流程：

``` text
Pod创建

↓

Scheduler

↓

选择Node

↓

绑定Pod
```

------------------------------------------------------------------------

# 2. Scheduler核心职责

Scheduler主要负责：

-   节点筛选；
-   资源评估；
-   调度策略执行；
-   Pod绑定。

Scheduler不负责：

-   创建Pod；
-   启动Container。

------------------------------------------------------------------------

# 3. Pod调度流程

完整流程：

``` text
用户提交Pod

↓

API Server

↓

Scheduler监听

↓

选择Node

↓

Binding

↓

Kubelet创建Pod
```

# 4. Scheduler工作架构

结构：


# 5. 调度阶段

Kubernetes调度主要包含两个阶段：

## Filtering

过滤阶段：

> 找出满足条件的Node。

检查：

-   CPU；
-   内存；
-   标签；
-   存储；
-   其他约束。

------------------------------------------------------------------------

## Scoring

评分阶段：

> 从可用Node中选择最合适的节点。

------------------------------------------------------------------------

# 6. Node资源评估

Scheduler会考虑：

-   CPU资源；
-   Memory资源；
-   GPU资源；
-   存储资源；
-   网络条件。

例如：

Pod资源需求：

``` yaml
resources:
  requests:
    cpu: 2
    memory: 4Gi
```

Scheduler寻找：

``` text
Node

CPU >= 2

Memory >= 4Gi
```

------------------------------------------------------------------------

# 7. Node Selector节点选择

nodeSelector是最简单的节点选择方式。

示例：

``` yaml
nodeSelector:
  disk: ssd
```

表示：

Pod只能运行在：

``` text
具有disk=ssd标签的Node
```

------------------------------------------------------------------------

# 8. Node Affinity节点亲和性

Node Affinity：

> 比nodeSelector更灵活的节点选择机制。

类型：

## required

必须满足条件。

------------------------------------------------------------------------

## preferred

优先满足条件。

例如：

``` text
优先SSD节点

否则普通节点
```

------------------------------------------------------------------------

# 9. Pod Affinity亲和性

Pod Affinity：

> 根据已有Pod的位置决定新Pod部署位置。

例如：

``` text
Web Pod

↓

靠近

↓

Cache Pod
```

优势：

-   降低网络延迟；
-   提高访问效率。

------------------------------------------------------------------------

# 10. Pod Anti-Affinity反亲和性

Pod Anti-Affinity：

> 控制Pod不要部署在同一个位置。

例如：

数据库副本：

``` text
Node1

mysql


Node2

mysql
```

目的：

-   提高高可用；
-   避免单节点故障影响全部副本。

------------------------------------------------------------------------

# 11. Taints与Tolerations

## Taint

Taint用于限制Pod进入节点。

例如：

``` text
GPU Node

禁止普通Pod运行
```

------------------------------------------------------------------------

## Toleration

Pod声明：

> 我可以接受这个节点限制。

关系：

``` text
Node Taint

↓

Pod Toleration

↓

允许调度
```

------------------------------------------------------------------------

# 12. 调度优先级

Priority：

用于控制：

> 哪些Pod优先获得资源。

例如：

生产业务：

高优先级。

测试任务：

低优先级。

------------------------------------------------------------------------

# 13. 抢占机制

资源不足时：

``` text
高优先级Pod

↓

驱逐低优先级Pod

↓

释放资源

↓

完成调度
```

# 15. 调度最佳实践

建议：

-   使用Node Affinity；
-   使用Pod Anti-Affinity提高高可用；
-   合理配置Taints；

# 16. 系统架构设计师考点

## Scheduler作用？

答：

> Scheduler负责为未调度Pod选择合适Node，并完成Pod绑定。

------------------------------------------------------------------------

## 调度流程？

答：

> Pod提交后，Scheduler根据资源、标签、亲和性等条件选择Node，然后通过API
> Server完成绑定。

------------------------------------------------------------------------

## Node Selector和Affinity区别？

答：

> Node Selector只能进行简单标签匹配，Affinity提供更灵活的节点调度策略。

------------------------------------------------------------------------

## Taint作用？

答：

> Taint用于限制哪些Pod可以运行在指定Node上。

# 18. 本节小结

Kubernetes调度核心：

1.  Scheduler负责Pod节点选择；
2.  调度包括过滤和评分两个阶段；
3.  Node Selector实现简单节点选择；
4.  Affinity提供灵活调度策略；
5.  Taints限制节点访问；
6.  Tolerations允许Pod进入特殊节点；
7.  优先级和抢占保证关键业务资源。
