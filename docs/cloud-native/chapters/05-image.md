# 1. Docker镜像概述

Docker镜像（Image）：

> 是用于创建容器的只读模板。

镜像包含：

-   应用程序；
-   运行环境；
-   配置文件；
-   依赖组件。

核心作用：

-   标准化应用交付；
-   保证运行环境一致；
-   快速创建容器。

------------------------------------------------------------------------

# 2. Image与Container关系

关系：

``` text
Dockerfile

↓

Image

↓

Container
```

说明：

-   Dockerfile用于描述镜像构建过程；
-   Image是静态模板；
-   Container是镜像运行后的实例。

------------------------------------------------------------------------

# 3. Docker镜像分层机制

Docker镜像采用分层存储：

``` text
Container Writable Layer

↓

Image Layer 4

↓

Image Layer 3

↓

Image Layer 2

↓

Base Image Layer
```

特点：

-   每一层只保存变化内容；
-   多个镜像可以共享基础Layer；
-   降低存储和传输成本。

------------------------------------------------------------------------

# 4. Layer层原理

例如Dockerfile：

``` dockerfile
FROM node

RUN npm install

COPY app

CMD npm start
```

构建后：

``` text
CMD Layer

↓

COPY Layer

↓

RUN Layer

↓

Node Base Layer
```

每条Dockerfile指令通常会产生新的镜像层。

------------------------------------------------------------------------

# 5. UnionFS与OverlayFS

UnionFS是一种联合文件系统。

Docker利用分层文件系统实现：

-   镜像复用；
-   Layer共享；
-   快速构建。

常见实现：

-   OverlayFS；
-   Overlay2。

------------------------------------------------------------------------

# 6. Copy-on-Write机制

Docker采用Copy-on-Write（写时复制）。

运行容器时：

``` text
只读Image Layer

↓

Writable Container Layer
```

特点：

-   镜像层保持只读；
-   修改内容写入容器可写层；
-   多个容器共享同一个镜像。

# 17. 系统架构设计师考点

## 为什么Docker镜像部署速度快？

答：

> Docker镜像采用分层存储机制，通过共享基础Layer减少数据传输，同时利用镜像模板快速创建容器。

------------------------------------------------------------------------

## 为什么多个容器可以共享同一个镜像？

答：

> Docker镜像采用只读Layer设计，多个容器共享底层镜像层，通过Copy-on-Write保存各自修改内容。

------------------------------------------------------------------------

## Docker镜像为什么轻量？

答：

> 镜像采用分层结构，并且容器共享宿主机内核，不需要完整操作系统环境。
