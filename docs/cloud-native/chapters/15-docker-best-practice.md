# 3. 镜像设计最佳实践

原则：

## 使用固定版本基础镜像

推荐：

``` dockerfile
FROM nginx:1.27
```

避免：

``` dockerfile
FROM nginx:latest
```

------------------------------------------------------------------------

## 一个镜像一个主要职责

推荐：

``` text
一个Container

↓

一个主要进程
```

------------------------------------------------------------------------

## 减少镜像大小

方法：

-   多阶段构建；
-   清理缓存；
-   使用.dockerignore。

------------------------------------------------------------------------

# 4. Dockerfile规范

企业Dockerfile规范：

-   固定基础镜像版本；
-   合理安排Layer；
-   不保存敏感信息；
-   使用非root用户；
-   保持构建过程可追踪。

示例：

``` dockerfile
FROM node:20

WORKDIR /app

COPY package.json .

RUN npm install

COPY . .

USER app

CMD ["npm","start"]
```

# 5. 容器运行规范

生产环境建议：

-   非root运行；
-   设置健康检查；
-   设置资源限制；
-   明确日志输出。

避免：

-   privileged模式；
-   无限资源；
-   调试容器长期运行。

# 9. Docker安全最佳实践

核心原则：

> 最小权限 + 纵深防御。

包括：

-   非root运行；
-   Capability限制；
-   Seccomp；
-   镜像扫描；
-   Secret管理；
-   网络隔离。

禁止：

``` dockerfile
ENV PASSWORD=123456
```

# 10. 资源管理规范

需要限制：

CPU：

``` bash

```

Memory：

``` bash

```

``` bash

```

目的：

防止单个容器影响整体系统。

# 18. 系统架构设计师考点

## Docker生产最佳实践？

答：

> 应从镜像、容器、存储、网络、安全、监控和自动化部署多个方面进行规范设计，实现稳定、安全、高效运行。

------------------------------------------------------------------------

## 为什么镜像需要版本管理？

答：

> 明确版本可以保证部署一致性，支持问题追踪和快速回滚。

------------------------------------------------------------------------

## 为什么容器需要资源限制？

答：

> 防止单个容器消耗过多资源影响其他业务，提高系统稳定性。

------------------------------------------------------------------------

## Docker如何向云原生演进？

答：

> Docker提供容器基础能力，Compose解决多容器管理，Swarm提供集群编排，而Kubernetes进一步提供企业级云原生平台能力。
