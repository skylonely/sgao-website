# 第一章：Git 为什么会诞生？

> **如果不了解 Git 为什么出现，就很难真正理解 Git。**

---

## 本章目标

读完这一章，你将理解：

- 为什么会出现版本控制？
- Git 解决了什么问题？
- Git 为什么能取代 SVN？
- GitHub 为什么会成功？
- 为什么今天几乎所有开发团队都使用 Git？

---

## 1. 没有 Git 的时代

假设你正在开发一个项目。

第一天：

```text
project/
```

第二天，为了防止改坏，你复制了一份：

```text
project_v2/
```

第三天：

```text
project_v3/
```

后来又变成：

```text
project_final/
project_final_new/
project_final_ok/
project_final_ok2/
project_final_最终版/
project_final_最终版2/
```

是不是很熟悉？

很多人最初就是这样管理代码的。

**问题：**

- 不知道哪个版本最新
- 无法知道谁修改了什么
- 无法回退
- 无法多人协作

于是，"版本控制"的需求出现了。

---

## 2. 什么是版本控制？

版本控制（Version Control）就是：

> **记录每一次修改，并允许随时查看历史、比较差异、恢复旧版本。**

如果把写代码比作写小说：

- 每天保存一个章节
- 能看到昨天改了什么
- 能恢复到一周前
- 能多人一起写

这就是版本控制。

---

## 3. 第一代版本控制

最早的版本控制工具有：

- RCS
- CVS

它们已经能够保存版本，但多人协作能力有限。

随着软件越来越复杂，出现了新的工具。

---

## 4. SVN 的时代

Subversion（SVN）曾经是企业开发的主流。

它采用：

```text
开发者
    │
    ▼
中央服务器
    ▲
    │
其他开发者
```

所有人都依赖一台中央服务器。

优点：

- 简单
- 权限管理方便

缺点：

- 服务器挂了，很多工作无法继续
- 提交速度受网络影响
- 分支和合并成本高

---

## 5. Git 的诞生

2005 年，Linux 内核项目需要新的版本控制工具。

Linux 创始人 **Linus Torvalds** 设计了 Git。

他的目标非常明确：

- 快
- 分布式
- 数据可靠
- 支持大量开发者协作

Git 很快成为 Linux 社区的标准。

---

## 6. Git 与 SVN 的核心区别

SVN：

```text
每个人依赖中央服务器
```

Git：

```text
每个人都有完整仓库

开发者 A
     │
完整历史

开发者 B
     │
完整历史

GitHub（共享）
```

这意味着：

- 可以离线提交
- 可以离线查看历史
- 每个人都有完整备份
- 分支创建几乎瞬间完成

---

## 7. GitHub 为什么成功？

Git 解决了版本控制问题。

GitHub 则解决了：

- 代码托管
- 团队协作
- Pull Request
- Issue
- 开源社区

Git + GitHub 的组合，逐渐成为现代软件开发的标准。

---

## 8. 今天为什么人人都学 Git？

现代开发流程几乎都会经过：

```text
需求
  │
  ▼
VS Code
  │
  ▼
Git
  │
  ▼
GitHub
  │
  ▼
CI/CD
  │
  ▼
部署上线
```

无论是前端、后端、移动端还是 AI 开发，都离不开 Git。

---

## 本章总结

Git 并不是为了"保存文件"。

它诞生的目的，是解决：

- 版本管理
- 团队协作
- 历史追踪
- 安全回滚

理解这一点，后续学习 Git 的所有命令都会更容易。

---

## ⚠️ 常见误区

**误区一：Git = GitHub**

不是。

- Git：版本控制工具
- GitHub：代码托管平台

---

**误区二：只有团队才需要 Git**

不是。

个人项目同样应该使用 Git，因为它能帮助你记录每一次修改，并安全回退。

---

## 🚀 推荐实践

- 从第一个项目开始就使用 Git。
- 每完成一个小功能就提交一次，而不是积累很多修改再一次性提交。
- 学 Git 时，不要只背命令，先理解它为什么会出现。
